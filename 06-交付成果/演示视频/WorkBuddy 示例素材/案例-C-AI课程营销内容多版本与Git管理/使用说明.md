# 使用说明

## 案例目标

围绕一个虚拟项目建立一个可以用 Git 管理的多版本营销内容仓库，并演示一次完整的多 Agent 营销内容生产流程。

## 案例主线

```
A：事实主版本
└── B：客群版本（企业版、个人版）
    ├── C：客群延伸版本 1（例如海报短文案）
    └── D：客群延伸版本 2（例如活动文案或邮件话术）
```

## 使用顺序

1. `02-Prompts/C01-生成事实主版本.md`
   - 作用：从审核资料生成统一事实卡 A，作为所有客群版本的唯一事实来源。
   - 预期：得到 `facts/fact-sheet-v1.0.md` 和首次 Git 提交说明。

2. `02-Prompts/C02-生成企业客户版本.md`
   - 作用：基于事实主版本生成企业版营销内容 B1。
   - 预期：得到企业版介绍稿、价值说明、常见疑问和事实来源映射。

3. `02-Prompts/C03-生成个人学习者版本.md`
   - 作用：基于事实主版本生成个人版营销内容 B2。
   - 预期：得到个人版课程介绍、学习路径、报名文案和事实来源映射。

4. `02-Prompts/C04-生成客群延伸版本C.md`
   - 作用：在 B（客群版本）基础上独立延伸出客群延伸版本 C。
   - 预期：得到主标题、副标题、行动提示和事实来源映射。

5. `02-Prompts/C05-生成客群延伸版本D.md`
   - 作用：在 B（客群版本）基础上独立延伸出客群延伸版本 D。
   - 预期：得到活动介绍页、邀约文案和销售话术草稿。

6. `02-Prompts/C06-查看并提交各版本.md`
   - 作用：演示 Git 一次性查看 A / B / C / D 四个分支的差异，并准备提交说明。
   - 预期：得到文件状态、版本差异摘要和各自提交标题。

7. `02-Prompts/C07-多Agent营销内容工作流.md`
   - 作用：设计“事实核验 / 客群策略 / 文案生成 / 合规审核 / 主编汇总”的多 Agent 协作流程。
   - 预期：得到角色契约、交接格式、串并行关系和一张完整的工作流架构图。

8. `02-Prompts/C08-最终发布前版本审查.md`
   - 作用：检查 A / B / C / D 四个版本的事实、来源、客群适配和合规边界。
   - 预期：得到可发布清单、需修改清单和最终 Git 提交建议。

## Git 演示注意事项

所有版本先以文件形式落盘，不直接执行 Git 操作。事实主版本、客群版本和延伸版本分别对应一个 Git 分支。提交说明中必须写明：父版本、事实源版本、变更内容和客群。一次演示最多展示 A → B → C 与 A → B → D 三层关系。

## 多 Agent 演示注意事项

多 Agent 工作流是 C07 输出的工作流架构图，不预先创建 Agent。每个 Agent 明确：输入、输出、禁止动作。下游 Agent 只能读取上游已经确认的产物。
