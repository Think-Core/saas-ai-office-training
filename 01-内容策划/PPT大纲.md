# PPT 大纲与页数预算

## 页数原则

- 当前已完成的页面统一按实际物理顺序使用 `A-xx`；新增、删除或移动页面时同步重排后续编号。
- 普通认知页按约 1—2 分钟一页估算；一页只承担一个清楚的讲述任务。
- 每个案例先用 3—4 页把场景讲清楚，再用 1 页独立播放录屏；需要时可在视频后增加 1 页结果复盘。
- 案例具体材料、流程和结论必须在实际研究与录屏准备过程中共同确定，不凭空编造。
- 当前基准方案约 42—44 页，按材料复杂度允许在约 38—49 页之间调整；这是页面预算，不是最终必须达到的数字。

## 第四章｜03 掌握人机协作

- 建议时间：约 8 分钟。
- 页面预算：8 页。
- 作用：讲一套不依赖具体 Agent 产品的方法论：按能力拆分任务、选择合适的中间工作格式，并用项目文件保存长期协作上下文。
- `A-25` 章节封面已确定：页面只保留大号编号“03”、标题“掌握人机协作”和副标题“定义 · 执行 · 验收”；完整复用 `A-03`、`A-13` 的字体层级、数字倾斜、紧字距、抽象蓝色光晕与整体留白。
- `A-26` 方法论开篇已确定：以“好厨具好食材，也需要好厨艺”说明工具能力不等于结果质量；建立“人定目标与验收—Agent 理解、规划与调度—专业工具计算、绘制与生成”的分层协作关系，并提出扬长避短、分层协作、结果验收三项原则。
- `A-27` 文档方法已确定：核心不是推荐统一使用 DOCX 交付，而是“先转换成 Agent 擅长的文本，再处理格式”。大模型更擅长理解和生成文本；Markdown 用字符标记标题、列表和层级，既保留必要结构，又减少复杂排版干扰。页面以 DOCX 输入—Markdown 工作稿—DOCX 交付作为制度或报告修订示例，下方四个语义节点依次说明读取结构、转换工作稿、修改确认、写回检查。
- `A-28` 数据方法已确定：Agent 负责理解问题、拆解任务和判断下一步；Python、SQL、CSV、JSON、表格与图表工具负责可重复、可检查的处理；人最终核对指标口径、异常数据、计算逻辑和结论。
- `A-29` 演示汇报方法已确定：先明确汇报对象，再根据受众、重点与信息关系编排汇报流程，判断采用线性讲述、深度阅读、实时数据或过程推演，最后从 PPT、网页报告、数据看板或动态推演中选择合适的呈现方式；不是先打开软件找模版，而是先判断信息怎样呈现最清楚。
- `A-30` 设计方法已确定：先用自然语言说明业务目标、使用对象、核心流程和参考风格，再让 Agent 快速形成可以讨论的想法原型；人结合业务流程、使用场景和实际反馈判断方向是否成立，专业团队继续完成视觉规范、内容完善、技术实现和质量把关。
- `A-31` 标题确定为“长期任务：对话是工作现场，文件是组织记忆”，页首概括为“把复杂任务拆开，把关键过程记录下来，把任务产物汇总起来”：长期目标拆成多个边界清楚的会话，每个会话开始前读取同一套项目说明、当前进展、决策、交接和产物，完成后把结果写回；新会话从最新状态直接接手，并用版本节点、分支和合并图表达变化历史。
- `A-32` 作为第三部分收束页，标题为“人定方向，Agent 推进，工具执行”：用一条闭环直观呈现人负责目标、边界、判断和验收，Agent 负责理解、规划、调度和整合，专业工具负责检索、计算、绘制和生成，最终形成文档、数据、汇报或原型；成果经“验收结果—反馈修正—进入下一轮”回到人。

## 第五章｜04 办公场景实战

- `A-33` 为第四部分章节封面，显示“04 / 办公场景实战 / 案例演示与方法迁移”，完整沿用前三个章节封面的冷白过渡视觉。
- 封面之后进入四个核心案例，统一用场景、输入、流程、人机分工、验收标准和录屏重点说明如何迁移前述方法。

- 建议时间：合计约 28—32 分钟。
- 页面预算：每个案例 5 页为基础，必要时增加至 6 页；合计约 20—24 页。

每个案例使用以下结构槽位：

1. **场景页**：为什么要做这件事，原流程哪里费时或容易出错。
2. **输入与成果页**：有哪些材料，最终要交付什么，给谁使用。
3. **方法或流程页**：WorkBuddy 如何参与，人和 AI 如何分工。
4. **验收与观看提示页**：怎样判断结果可用，录屏时重点看什么。
5. **独立录屏页**：以视频为主体，不与大段说明挤在一页。
6. **可选复盘页**：只有案例结果复杂、需要前后对照或总结方法时才增加。

四个案例方向保持不变：

- 从零散工作记录生成周报；
- 多份材料生成阶段性工作总结；
- 营销策划与配套素材；
- 从零散资料形成可持续使用的知识库。

现阶段只保留这些结构槽位。做到某个案例时，再共同寻找材料、确认真实场景、设计录屏并填写页面内容。
